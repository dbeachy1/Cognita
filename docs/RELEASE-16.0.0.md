# Cognita 16.0.0 release notes

Development record only. Qualification, release review, publication, and verified 16.0.0 download assets are pending; this document does not announce a published release.

This source candidate adds the audiobook source, generation, take, and build workflows. The combined connector API advances from v5 to v6 for its expanded catalog and typed book/storage contracts. Workspace remains v3; the PostgreSQL schema remains 1; the Workspace metadata schema remains 1; and the Toolbox remains 12.6.0.

Audiobook imports reserve a durable job before source access, bind source access to the authenticated principal, project, connector, and Workspace callback, and recheck current permission before registering a take. Workspace credentials are not retained in durable jobs. Import and build workers keep ownership of their exact staging or media work through cancellation and shutdown. Prepared chapter history, generation evidence, and accepted build state remain distinct, so later plan changes do not rewrite a pinned historical take.

The focused source checks cover actual gateway-to-engine Workspace import, both JSON-RPC and connector batches, concurrent authenticated principals, credential revocation before transfer and before finalization, a plan refresh during transfer, import/build media-thread shutdown ownership, and bookmark publication recovery. The complete provider-free, two-chapter production walkthrough is in [`examples/audiobook/synthetic_16_walkthrough.py`](../examples/audiobook/synthetic_16_walkthrough.py). It exercises native PCM import, chapter and whole-book 192 kbps MP3 builds, exact recipe inspection, one-chunk reuse/retake, stale-head reporting, rollback, readers, generation/job history, and full project backup/restore. Running it against the packaged Linux FFmpeg/ffprobe configuration remains part of the release gate.

The Linux trial and offline reference-Windows installation can be tested with the available bundles. The normal Windows Setup path copies source and runs `cognita update --no-pull`; its release payload still needs the published service image digests for `stage_published`. Those digests do not exist until the reviewed release is published, so a successful local build or placeholder digest would not establish that the normal Setup payload is ready. GitHub publication remains held for Doug's review.

No 16.0.0 installer or source archive has been verified or attached. The latest verified downloads remain the [Windows installer 15.7.0](https://github.com/dbeachy1/Cognita/releases/download/v15.7.0/Cognita-Setup-15.7.0-r1.exe) and [Linux source installer 15.7.0](https://github.com/dbeachy1/Cognita/releases/download/v15.7.0/cognita-src-15.7.0.tar.gz). Do not treat this development record as a published release.

The client-owned connector catalog must be refreshed after deployment. Recreate the affected connector and verify combined v6 and Workspace v3 before treating client-visible contract verification as complete.
